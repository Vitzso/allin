# Threat model

This covers the threats listed in section 3 of [PROJECT_SPEC.md](../PROJECT_SPEC.md), for the M0 foundation, the M1 OpenFit import, the M4 live market feeds, and the Linux server install. On Linux only part of the Docker install has run, once, on one box (see Still unverified). Data flows are in [IMPLEMENTATION.md](IMPLEMENTATION.md). This is a working document written from the source and its tests. It is not an independent security audit.

**What's protected:** task records, preferences, Health summaries (workout days and weights imported from OpenFit), encrypted backups, and, if you turn Alpaca on, your Alpaca key. Market prices are public, but which symbols you watch and when are not. Prices are synthetic until you turn a feed on, and AllIn places no orders either way.

**Assumed trusted:** the macOS user account while it is logged in (on Linux, the `allin` account and root on the box), the browser, the source tree, `dist/`, and installed dependencies.

| Stale or misleading market data  | Each row says whether it is replay or live, with provider, venue, and age. A price over 3 minutes old, or an expected bar over 5 minutes late, marks the row Stale and pauses signals. So does a provider that keeps answering while a row's newest bar falls more than 3 bars behind: the row reads Stale, dated from that bar, and the feed stays unreconciled, so nothing on it alerts. Catching up after start, sleep, or a failure also pauses signals, and setups found during a catch-up are labelled Historical and never alert. A setup alerts only if the feed was live, the bar is the newest closed bar, the bar before it was already held, and it arrived within 5 minutes of its close. A bar's closing price is re-checked, and a changed close restarts the rule's warm-up and marks any alert Corrected. Stock bars outside the session are dropped. Gaps, corrections, unclosed bars, and dates outside the calendar cannot produce a setup. No synthetic number appears under a live label. ## Known platform limits

- An unlocked host can read the plaintext it needs for local processing.
- Deleting data doesn't remove it from older backups, OS backups, or SSD snapshots.
- Verified on macOS on Apple Silicon only. **Linux has not been run on a real machine.** Other hosts are rejected by the launcher.
- The worker's sandbox on a Mac is deprecated by Apple (`sandbox-exec`).
- **On Linux the sandbox contains the worker's file system only.** The worker shares the host's network and can reach any address and port, including `127.0.0.1` and your WireGuard address, over plain HTTP as well as HTTPS. It can start other programs under `/usr`. The Mac sandbox is stricter, and narrowing the Linux worker's network needs its own design.
- Bubblewrap depends on unprivileged user namespaces, which some distributions restrict. Docker's default settings block them, so the Docker install runs without live feeds.
- **In the Docker install, anyone who can use Docker on the box (root, or a member of the `docker` group) can read both volumes**, and together with the passphrase that opens the vault. The container shares the host's network. On a box where WireGuard runs in a container, AllIn's container shares that container's network instead: the sign-in page is then reachable from every peer that container accepts, from the WireGuard container itself, and by anyone who can use Docker on the box; each container can reach what the other listens with; AllIn's container can open connections to the WireGuard peers and out through that container's routes; and AllIn is cut off whenever the WireGuard container restarts, until you restart it.
- Once this version unlocks an existing vault, or creates a vault or a backup, an older copy of AllIn can no longer open that vault or restore that backup (scrypt N=131072).
- Windows and Android have no sandbox for the worker yet.

## Still unverified

- **Coinbase's terms:** their page refused the automated request, so the terms haven't been read, and the link in the dialog (`https://www.coinbase.com/legal/developer-platform/terms-of-service`) hasn't been confirmed.
- **Alpaca's terms:** not read. A second-hand quote of a support article says data can't be redistributed. Viewing it privately shouldn't be affected, and installers must never include a key.
- **Alpaca on real data:** nothing beyond a 401 with no key has run. Stocks are proven only against the documented format, not real responses. Still to check: whether IEX bars arrive within minutes on the free plan, and whether they include hours outside the regular session.
- **Bar settling:** Coinbase bars were sampled across one close, on a quiet Saturday. The close re-check covers the risk.
- **Keychain inside the sandbox:** the profile denies the Keychain services, but it hasn't been proven that they are blocked.
- **`sandbox-exec`** is deprecated.
- **The Linux sandbox:** `tests/feedSandboxLinux.test.ts` has never run, so the bubblewrap worker, its containment proof and its behaviour under the systemd unit are unproven.
- **The Linux installer and unit:** only checked with `bash -n` and a packaging test on a Mac.
- **The Docker install:** on 2026-11-16 one box built the image and started the container, in the variant for WireGuard in a container (a second compose file that shares that container's network). AllIn passed its start checks, and a phone on the WireGuard network reached it over HTTPS and got AllIn's own refusal, `Cross-site access is not allowed.`, after its owner continued past a certificate warning. No sign-in page was shown. Nothing else has run: not creating a vault or signing in there, not that the feed refuses to run, not the restart after the WireGuard container restarts, not the start order after a reboot, and not the host-networking variant at all. Its tests are text checks, plus the Linux test that a missing `bwrap` means isolation is unavailable and no worker starts, which has itself never run.
- **The native modules on Linux:** both were installed in the Docker image on one box, and `@napi-rs/keyring` loaded when AllIn started there. `better-sqlite3-multiple-ciphers` loads its binary only when a vault is opened, which hasn't happened on Linux. `@napi-rs/keyring` is still loaded there even though a key file holds the device secret.
- **A sign-in over WireGuard,** from a phone and a Mac, and whether their browsers accept the private authority and its name constraint.
- **The box's disk is encrypted,** and **the distribution:** assumptions you confirm, not facts. An unencrypted disk leaves the key file readable to someone who takes it.
- **Systemd hardening beyond the four lines in the unit:** not tried with bubblewrap.

## Before later milestones

- **M3 (local model):** give the model no storage, network, or tool access. A deterministic policy checks every proposal. Prove that a malicious note can't trigger a write.
- **M5 (release):** run packet capture and disk inspection, verify the Keychain policy, review dependencies, and sign the release.
